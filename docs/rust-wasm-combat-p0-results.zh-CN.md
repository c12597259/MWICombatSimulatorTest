## 发现的长随机流兼容问题

现有 Mulberry32 基准用不断增长的 JS Number 状态，每次加 `0x6D2B79F5`，没有把累计状态限制为 u32。超过 `2^53` 后发生舍入，产生与常规 wrapping-u32 不同的随机序列。

实测种子 1：第 **4,917,760** 次首次不同，旧流为 `0.9146185866557062`，常规 u32 流为 `0.26924679218791425`。种子 `0xFFFFFFFF`：第 **4,917,758** 次首次不同。72h 场景已跨过边界，只校验前一百万次会漏掉问题。

本步保留旧流，未改变固定基准结果或正式页面的 `Math.random`。公开向量覆盖四个种子到 600 万次，并验证“f64 累积状态 + 显式 JS ToUint32 + u32 混合运算”的兼容路径。Rust 阶段按此实现，再用完整战斗确认。若以后更换 RNG，独立编号和验证，不能重写已冻结参考。
