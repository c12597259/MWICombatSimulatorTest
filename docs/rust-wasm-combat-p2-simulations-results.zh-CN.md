# Rust/WASM P2.3 连续模拟、统计与性能

日期：2026-10-01。P2.3 已完成，P2 单图纵向检查点通过：19 个连续场景、113,295 个事件在冻结 JS、本机 Rust、实际 WASM 和当前 Edge JS 中得到相同结果与随机次数。**性能初测中 WASM 原型约比 JS 慢四倍**，尚不满足默认切换门槛。正式页面继续使用 JS，本轮没有生产构建、推送或部署。

## 实现与参考

复用 P2.2 事件核心，增加 zone、simulation 和 result 模块，实现地图抽怪/强度终止/每十场 Boss、地下城固定与随机波/完成循环/团灭重启、普通地图复活、迷宫尝试/严格大于 120 秒超时和箱子增益。

完整结果包含伤害直方图、经验、死亡、消耗品、HP/MP 回复/消耗、缺蓝与存活区间、掉落倍率、地图及迷宫字段、200 条环形团灭日志和每 1000 事件的 HP/MP 采样。分段运行保留队伍、队列、统计与 RNG，可查询进度及释放句柄。

保留原 JS 行为：地下城团灭只删除指定事件种类；后续重置保留玩家冷却；通关后回血回蓝而不额外清状态；同 HRID 复用存活账目；结束时不补结算活跃的存活/缺蓝区间；最后事件可超过时限；保留 minDungenonTime 等原拼写。核心 wipeEvents.timestamp 是诊断标记 runtime-clock，作为唯一现实时间字段排除比较，P4 正式消息适配时补实际 ISO 时间。其余字段及数组顺序严格比较。

期望来自 P0 不可变源码归档及原始 bundle。逐份核对源码/数据 SHA256，参考模块列表禁止混入当前战斗 src。参考执行真实冻结 CombatSimulator、Zone、Labyrinth 与 Worker 构造逻辑，生成要求 Node 18.16.1 / V8 10.2.154.26-node.26。前九场景另与不可变 P0 bundle 比较完整结果、RNG 和事件计数；没有修改 P0 固定结果或数学函数，也没有用 Rust 生成期望。

当前浏览器 JS 使用现有 src，构建前要求其战斗源码/数据字节与冻结版本相同。输入均为公开定义和人工队伍，没有读取真实账号配置。

## 首次差异与修复

长战斗发现并修复：

- 存活与缺蓝时长须按 old + (end - start) 累加，另一种括号顺序会产生末位差异。
- 迷宫宝箱原始增益包含字符串 startTime 等字段，须按公开定义解析，保持公会、地图/宝箱、额外增益的合并顺序。
- JS 技能增益对象跨目标和多次施放共享，刷新 startTime 会影响仍持有该对象的单位。Rust 为技能增益分配实例标识，刷新相应引用时间，保留原属性重算时机。

第三项首次出现在 dungeon-hpmp 第 **743** 个事件：ice_spear 刷新旧怪物持有的增益时间。长场景后来出现回复统计及战斗路径差异。增加第 731–760、1001–1030 事件等回归窗口后，两个长地下城场景完整对齐。

诊断比较事件、对象状态、完整堆、统计操作/累计结果、地图状态及 RNG，输出窗口内首次不同事件、字段路径及前序事件：

```powershell
# 参数：案例编号、起始事件偏移、窗口长度
npm run diagnose:simulation -- 1 0 1100
```

偏移 0 从首次事件开始；非零偏移只报告窗口内首次差异，不冒充全程首次差异。详细快照写入忽略目录 .bench/simulation-first-difference.json，终端只输出事件/字段诊断。窗口最多 10,000 事件，偏移最多 1,000,000。工具测试改变第四/第八事件的 RNG 次数，确认定位第四事件。

## 浏览器性能初测

人工五人海盗 T2，模拟 2h，种子 7。真实 JS/WASM Worker 返回完整结果；计时含输入规范化、JSON、Worker 往返及结果序列化。冷运行新建 Worker 并含初始化；热运行复用 Worker，额外预热一次后各测五次，交替顺序。正式 Worker 池/UI 尚未接入，以下是原型端到端计时。

最终计时单独运行 P2.3 两页，其他迁移测试已结束。两条路径使用同一构建，不能把绝对时间变化归因于 URL。原始样本保存在浏览器报告中。

| 路径 | 冷 JS | 冷 WASM | 热 JS 中位 | 热 WASM 中位 | JS/WASM |
| --- | ---: | ---: | ---: | ---: | ---: |
| 根路径 | 419.5 ms | 1005.3 ms | 206.6 ms | 877.6 ms | 0.24× |
| Pages 子路径 | 704.6 ms | 1594.9 ms | 372.9 ms | 1439.9 ms | 0.26× |

WASM 慢约 3.9–4.2 倍，达不到计划要求的主要长场景至少 2× 提速。尚未剖析热点；动态 JSON 统计、属性计算/序列化和共享增益引用扫描是待测候选，不能未经测量断言占比。P3 补规则组合时加入剖析，优化后仍须 P5/P6 长跑及正式端到端验收。没有用原 Node 72h 基线或另一份私有队伍宣称提速。
