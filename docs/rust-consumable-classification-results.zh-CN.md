# Rust 消耗品分类判断优化

日期：2026-10-05。基线为 `codex/rust-wasm-migration` 的 `90ce907`，已包含触发条件预解析和存活单位列表复用。本轮只修改 Rust 消耗品的分类表示及四处使用点。

## 实现与语义

创建消耗品时，从 `categoryHrid` 计算 `is_food`、`is_drink` 两个独立标志，替代运行时保存的类别字符串。触发检查、实际消耗的冷却和饮料 buff 加成直接读取标志，消耗品克隆也不再复制类别字符串。

保留原来的大小写敏感子串语义：`seafood` 仍命中 food，混合名称可以同时命中 food/drink，未知名称、空值、非字符串都按原规则处理。触发资格判断仍优先使用食物加速；实际消耗时，正的饮料浓度仍优先于食物加速。类别标志来自物品定义，当前加速、浓度和冷却照常读取实时状态。

- 最终源码及 WASM 与已测试、已计时的冻结候选逐字节/哈希一致。

## 计时方法

沿用本机重建的 11 个三人队伍配置，各模拟 24 小时、种子 7，Edge 154.0.4258.37 中实际 WASM Worker 串行运行。

开始正式矩阵前，连续交替执行两个版本至少 30 秒，本次共 16 次，以减少此前观察到的启动阶段波动。之后每版本、每配置预热一次，正式运行四次，交替先后顺序。矩阵共 110 次（22 次预热、88 次计时），每配置取四次计时的中位数；偶数中位数为中间两个值的平均。

计时包含模拟、结果序列化和 JSON 解析，不含引擎初始化、结果哈希和 Playwright 回传。16 次稳定预热、110 次矩阵运行的完整结果哈希、随机数调用次数和事件计数均通过检查，并与此前 JS 的结果哈希和随机调用次数比较；只排除日志中的现实时间戳。

这是固定重建输入的新对照，不是导出历史的随机回放，也不是线上多 Worker 批量模拟的总耗时。原始输入、源码快照、版本产物、逐轮记录和脚本保存在忽略目录 `.bench/rust-consumable-stage4/`，不提交、不上传。

## 热点采样

正式计时结束后，对巫师之塔 T4、地狱深渊 T3、魔像洞穴 T3 分别预热一次并采样两次，CDP 间隔 1 ms，剔除 idle；九次结果检查全部通过，这些运行不计入上表。

`is_contained_in` 与 `StrSearcher::new` 的自身样本合计从上一轮的约 8.1%～10.8% 降到本轮的 0%～0.4%；零表示没有采到，不表示整个程序绝不调用字符串搜索。消耗品触发流程（含子调用）在三个配置中分别占 7.8%、7.4%、6.9%，上一轮分别约 16.0%、17.6%、16.9%。这些占比受采样和内联影响，包含子调用的项目不可相加，也不等同于可节省时间。

下一处可测方向是结果统计：`SimResult::apply` 含子调用约占 16.3%～18.2%，其中 `result::increment` 约占 8.2%～10.4%。可以先减少每次累计统计时的重复 JSON 键查询和临时对象分配，再考虑结构化累计；必须保留更新顺序、浮点累加顺序及最终结果格式。
