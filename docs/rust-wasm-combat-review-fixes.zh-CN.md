# Rust/WASM：历史单位回收与团灭队列顺序修复

日期：2026-10-02。修复前基线：`5e942c0`。正式页面仍使用 JS。

## 历史单位回收

连续模拟每处理完 64 个事件，回收当前队伍、当前敌方和事件队列都不再引用的单位。队列的 `source`、`target`、`sourceRef` 均作为保留依据，因此死亡来源的延迟伤害、换波后仍待执行的事件和不在敌方列表中的晋升单位仍可访问原对象。收集发生在事件及触发器执行、统计写入完成之后，频率不依赖调用方的 chunk 大小。

存储槽可复用，对象 serial 单调递增。句柄同时检查槽位和 serial，旧句柄不能命中新对象；对外 JSON 继续输出原来的数字身份。共享技能 buff 身份使用 serial，不使用可复用的槽位。存活角色持有的 buff 值继续保留，刷新扫描不再遍历已回收单位。

固定遭遇和诊断快照保留完整历史对象，以兼容冻结 JS 快照。连续诊断在跳过 `startEvent` 之前就启用历史保留，避免丢失偏移之前的单位。普通连续模拟启用回收。

单人公开队伍、螃蟹 T0、种子 7、72 小时，在独立初始化的 WASM 中测量：

| 模拟时间 | 修复前线性内存 | 修复后线性内存 |
| --- | ---: | ---: |
| 1 小时 | 20.19 MiB | 17.06 MiB |
| 24 小时 | 86.13 MiB | 17.06 MiB |
| 72 小时 | 298.94 MiB | 17.06 MiB |

该场景完成 36,739 次遭遇、处理 181,279 个事件，结果 JSON 为 14,051 字节，没有团灭日志。新增自动测试验证修复后与冻结 JS、原生 Rust 的完整结果一致，并约束第 1 小时之后的内存增长小于 8 MiB、最终线性内存小于 64 MiB。此测量是 WASM 线性内存，不是浏览器进程总内存；输出日志和可选时序本身仍可能随模拟长度增长。原始本机记录位于忽略目录 `.bench/review-rust/memory-fixed.json`。

## 团灭队列顺序

普通地图全队死亡时，恢复 JS 的两步操作：先删除普攻事件，再从变更后的堆删除施法事件。一次合并筛选虽然删除相同事件集合，却改变 heap-js 剩余堆布局和同时间事件的顺序。

公开回归 `normal-wipe-preserves-separate-attack-cast-removal` 使用种子 `2958411238`。旧 WASM 在第 145 个事件的 `heap[4].id` 出现 `155 / 151` 差异；新 Rust 和新 WASM 均完全匹配。覆盖检查还要求死亡前同时存在普攻和施法事件，死亡后两种事件都已清除。
