# Rust / WASM 触发器与攻击调度分配优化结果

日期：2026-10-01。继装备缓存与 Buff 查询索引后，本次减少单场模拟的触发器检查和攻击调度中的重复分配。正式页面继续使用 JS，P3 全规则与数值边界仍待继续。

## 问题与改动

上一轮真实 Edge Worker 的 release WASM 采样中，触发器检查包含子调用占模拟栈约 25.5%，触发器数组克隆约 8.1%。消耗品检查在判断冷却和条件前复制整份对象；安排下一次攻击时复制整组技能，包括效果、增益、字符串与触发器。只读条件检查还会复制两侧队伍及过滤后的存活单位数组。

本次改动：

- 消耗品借用原对象检查冷却和全部条件，仅在通过后复制执行效果所需的快照。
- 攻击调度按原槽位索引借用技能，只复制 mana cost / cast time 等标量，保留空槽、顺序、首个可用技能和优先技能缺蓝时跳过后续技能的行为。
- 只读触发器检查借用两侧单位列表，存活数量、最低血量比例和属性求和直接按原顺序迭代，不创建中间数组。

实际消耗品/技能效果执行和可能改变角色、目标或对象身份的流程仍保留需要的快照。没有跨事件缓存触发条件、目标或冷却结果。一次消耗品执行后，后续槽位仍读取更新后的状态；每轮两侧的存活单位快照、食物先于饮料及循环到无触发的顺序保持。触发条件仍全部检查，首个失败后不提前短路。

没有改变公式、RNG、事件队列、结果字段、定义数据、JS 引擎或原有两项属性优化。

## 正确性

新增四个冻结 JS 固定遭遇，共 94 个事件快照：

- 有空技能槽，优先技能触发但缺蓝，后续可负担技能仍不执行。
- 优先技能条件失败，后面的有效技能按原槽位执行。
- 食物回复改变后续食物条件，回复受上限约束；饮料添加的 Buff 被后面的饮料观察到；冷却和再次检查保持状态。
- 两侧都有存活和死亡单位，多条件联合验证数量、最低血量比例、求和及首个存活目标。

覆盖审计检查冻结轨迹里实际出现的缺蓝记录、技能执行和首轮消耗品顺序，防止配置没有进入相关分支。期望仍由不可变 P0 源码和 Node 18.16.1 / V8 生成；未覆盖 P0 源码归档、bundle 或原九场景固定结果，没有扩大容差。

## 同轮性能比较

同一独立 Edge 154.0.4258.37、同一份已规范化公开人工输入、相同 WASM 模块 Worker 包装，比较 JS、优化前 `61cd923` 和优化后。样本为五人海盗 T2、2h、种子 7，共 31,962 个事件 / 140,680 次 RNG。各预热两次，七轮轮换顺序，计时包括 JSON、实际 Worker 往返与完整结果序列化，不含结果校验和 Playwright 回传。30 次冷/预热/热运行均匹配冻结完整结果。

| 引擎 | 七次热运行中位数 |
| --- | ---: |
| 当前 JS | 354.0 ms |
| Buff 索引 WASM（本次优化前） | 527.1 ms |
| 本次减少分配的 WASM | 365.0 ms |

本次 **提速约 1.44×，耗时减少约 30.8%**，WASM 为同轮 JS 耗时的约 **1.03 倍**，这个样本已接近 JS。原始样本、计时范围和两版指纹在 `.bench/trigger-optimization/benchmark.json`。存在运行波动，不能将两轮绝对毫秒值混算，也不推广到其他队伍、72h 或正式 Worker 池。

现有原型页面的另一组含输入规范化的端到端测量：根路径 JS/WASM 热中位 346.3/367.8 ms，Pages 为 310.8/358.5 ms。范围和包装与上述比较不同，保留为独立交叉检查，不合并计算优化倍数。当前仍未达到主要长场景 WASM 至少快于 JS 2 倍的默认切换门槛，正式页面继续 JS。

## 优化后的热点

保留上一轮精确匹配旧构建指纹的 `.bench/buff-cache/profile-after`；本次新采样保存在 `.bench/trigger-optimization/profile-after`。两次都使用真实 Worker 和相同公开场景，排除 idle，仅统计 WASM 模拟栈：

| 调用（含子调用） | 优化前 | 优化后 |
| --- | ---: | ---: |
| 触发器检查 | 25.5% | 14.2% |
| 触发器数组克隆 | 8.1% | 0.6% |
| 属性重算 | 19.5% | 25.8% |
| 结果统计 `SimResult::apply` | 9.2% | 13.0% |

优化后攻击调度约 5.5%，战斗日志 `full_log` 约 10.1%。属性/统计的相对占比随其他开销减少而上升，不能据此断言这些函数变慢。函数占比互相重叠，编译内联与采样会影响归属，不能相加，也不将两次 profile 的绝对时间用于提速结论。

下一部分优先评估统计和战斗日志中的动态 JSON 构造、查找与复制，再继续属性热路径；保留当前结果字段、日志顺序和浮点累计顺序。此次没有提前执行这些改造。
