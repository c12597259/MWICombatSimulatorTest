## Rust 本轮改动

`AttributeUnit::update` 原来每次执行 45 次 `format!` 构造属性或 buff 名称，随后用名称分派到结构体字段。现在等级、增幅、恢复、抗性和掉落等 buff 使用固定字符串，属性直接读取或修改对应数值字段；近战、远程、魔法的命中/伤害/闪避使用有序数值元组。

原先还会克隆整个 `CombatDetails`，其中旧 `combat_stats` 最后又被新结果覆盖。现在在所有可能失败的操作完成后直接修改派生字段，保留当前 HP/MP 及其他未更新字段，避免这份无用克隆。

逐项计算顺序、buff 生命周期、事件调度、模拟时长均保持不变。暂未改动 buff 分组方式、排序、怪物基础属性缓存，便于单独衡量本轮收益。

## 正确性验证

- `npm run test:attributes`：3,482 个属性场景（2,245 配装、1,044 怪物、127 永久增益、66 生命周期），native 与 WASM 均与冻结 JS 一致，另有输入与比较器检查。
- `npm run test:simulations`：56 项完整战斗/轨迹/内存检查，加 6 项专精护符检查通过，覆盖 24 小时地下城完整日志、72 小时普通地图和单位回收。
- `cargo test --workspace --locked`、`cargo fmt --all -- --check`、workspace/all-targets Clippy（warnings 视为错误）通过。

JS 优化使实时 JS 源码不再与旧源码逐字节相同。模拟测试准备器因此区分两种用途：native/WASM 回归仍从校验过哈希的冻结源码生成基线，并检查冻结结果、游戏数据；浏览器“只比较运行时差别”的审计默认仍要求实时 JS 源码相同。没有更新或放宽数值正确性基线。

## 计时方法

修改前已保存旧版 WASM 和胶水代码。修改后的 WASM 使用同一编译流程和 release 配置。两个版本分别在独立 Edge Worker 内初始化，然后串行交替运行用户历史重建的 11 个三人队伍配置，每个模拟 24 小时、种子 7。

每个配置、每个版本预热一次，再运行三次取中位数。计时包含模拟、结果序列化和 JSON 解析，不包含模块/游戏数据初始化、结果哈希和 Playwright 回传。两个版本都检查完整结果哈希、随机调用次数、已处理事件数和事件类型计数，并对照前轮 JS 的结果哈希和随机调用次数。

历史缺少原始种子和额外增益，所以这是使用相同重建输入的新对照实验，不是历史战斗回放。原始队伍、WASM、逐轮结果和本机脚本保存在忽略目录 `.bench/rust-attributes/`，不提交或上传。
