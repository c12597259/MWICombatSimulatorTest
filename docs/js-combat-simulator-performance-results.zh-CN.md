# JS 战斗模拟优化：首轮实测

日期：2026-09-21。优化前代码：`7440b0e`。没有改变战斗规则或减少模拟时长，也没有用多次短模拟代替连续长模拟。

## 做了什么

1. 装备基础属性缓存：装备槽位、对象、HRID、强化等级或物品定义改变时失效；战斗中的增益变化不再重复求装备总和。
2. 每次属性重算只扫描一次战斗增益，保留原先累加顺序；神龛等级每次重算只标准化一次。缓存不跨增益修改保留。
3. 去除每个事件的无用 `await`。进度通知最多约每 250 毫秒一次，结束强制 100%；HP/MP 仍按原事件间隔采样。
4. 事件队列查询不再复制整个堆；删除保留旧算法顺序。没有启用会影响同时间事件顺序的延迟删除。
5. 批量地图和迷宫复用 Worker，通常最多 8 个，低内存设备最多 2 个，并尽量给页面保留一个核心。成功或出错后释放整个池。
6. 增加生产构建。用户脚本保持原文，避免压缩时丢失安装元数据。

性能分析显示，最大收益来自前两项，不是单纯取消异步或开启多线程。单次模拟仍是一条连续、单 Worker 的战斗时间线。

## 验证范围

- 原有自动测试：64 项通过。
- 新增自动测试：11 项通过，覆盖装备修改后缓存失效、增益顺序、5000 次事件队列操作、团灭记录、HP/MP 采样、进度结束、Worker 并发限制/复用/结果顺序/错误清理。
- 六个短场景的新旧结果哈希及随机数调用数完全一致：不同种子的地下城、开启 HP/MP 的地下城、单人频繁团灭、三人海洋星球、单人地狱深渊、独眼巨人迷宫。
- `npm run build:production` 成功；仍有 webpack 资源体积警告，不是构建错误。
- 浏览器五人导入和 72 小时地下城完成，页面无控制台错误。
- 全图批量、全迷宫、历史及计划界面的完整交互复查尚未完成：后续浏览器连接不可用。核心迷宫、调度以及历史/计划数据逻辑自动测试不等同于这项 UI 验收。

## 保留事项

- 种子仅用于独立基准，不写入页面历史。本次不扩大历史记录格式。
- 未测峰值内存和完整 GC 占比；基准中的 `memory` 是每次运行结束的进程读数，不能当作峰值。
- 单次去 Promise 的收益较小，保留它是因为代码更直接且一致性通过。没有逐项执行“低于 5% 就回退”的原始建议。
- 与 Metz 的 DPS 差异及地下城换波规则，需要独立验证。本次保持旧结果，不以另一模拟器作为真值。
- 暂不启动 WASM；若以后仍需要接近 4 秒，可基于现有确定性基准另行评估。
