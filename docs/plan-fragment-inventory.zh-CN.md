# 计划按已有钥匙碎片计算剩余刷取时间

2026-09-27：已实现并完成本地测试和生产构建。通过 `testing` 分支的 GitHub Pages 发布，线上入口为 `/MWICombatSimulatorTest/dist/`。

计划的「角色汇总」新增「刷图目标抵扣已有钥匙碎片」开关，默认启用。
沿用现有私有插件库存桥接，不需要修改插件、同步服务器或 FRP。
库存独立读取，不写入模拟历史或保存的计划，也不会实际扣除游戏物品。

## 计算方式

- 每名角色单独按碎片种类汇总整个计划的需求，共享碎片只抵扣一次库存。
- 完整钥匙目标仍按四种碎片各 0.9 个/把展开，不改变原制作期望口径。
- 例如 D1、D2 各需 100 把钥匙，共享的紫色碎片总需求为 180；已有 100 时只需再刷 80。
- 按计划步骤顺序分配库存。前一步为等队友而多刷出的碎片，可以继续满足后续步骤；已分配给独立碎片目标的数量会被保留，不能再拿去做另一个目标的钥匙。
- 每张图的组队时间为各队员「剩余缺口 / 该记录中的个人掉率」的最大值，各图按步骤顺序累加。不同队伍、配装或掉率的历史不会被合并成一条虚构记录；此功能不自动寻找最优路线。
- 一名队员库存足够时仍会陪同队伍刷图，因此其预计刷得数量可能超过自己的缺口；全队库存足够时该图耗时为 0。零缺口不要求正掉率。
- 经验、预计所得、消耗品用量和消耗品准备时间均使用重算后的战斗时长。后续钥匙目标使用前序富余时，最终所得不会重复计入已耗用的碎片。

## 界面和数据

每步地图显示每名角色的本步库存抵扣、前序富余和还需刷取的数量。
每名角色的汇总表显示「计划总需求、库存已有、剩余需刷、预计刷得、刷图时间」。
修改前一步数量时，所有后续步骤和汇总同步重算；开关按计划保存。

角色通过历史专业快照中的 characterId 匹配库存。缺少完整库存时显示「未知」，对应角色按未抵扣估算；总耗时也会说明这一点。
「读取最新库存」沿用现有刷新流程，库存时间仍显示在角色详情中。缺少角色标识的旧历史需重新导入并模拟。
历史选择未完成或队伍不匹配的步骤不占用库存、不计入有效汇总，并阻止显示完整计划耗时。

本次抵扣范围是钥匙碎片；已有成品钥匙和宝箱不抵扣刷宝箱目标，地下城开箱钥匙需求仍按原规则显示。
关闭碎片抵扣时恢复完整需求估算，前序刷图富余仍能满足后续需求。消耗品库存模式独立设置。
