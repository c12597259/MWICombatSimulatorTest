# Rust 怪物基础属性缓存与 buff 索引实验

日期：2026-10-04。基线为本地 `codex/rust-wasm-migration` 的 `b309751`，已包含上一轮直接字段访问优化及专精护符修复。本轮不改动线上 JS。

## 优化前采样

使用 Edge 154 的实际 WASM Worker，对巫师之塔 T4、地狱深渊 T3、魔像洞穴 T3 各预热一次，再采样两次 24 小时模拟。采样间隔为 1 ms，剔除 `(idle)` 样本后的结果如下：

| 函数 | 巫师之塔 T4 | 地狱深渊 T3 | 魔像洞穴 T3 |
| --- | ---: | ---: | ---: |
| 属性重算（含子调用） | 28.1% | 33.7% | 33.8% |
| buff 查找（自身） | 5.2% | 6.5% | 6.9% |

百分比有采样误差，包含子调用的项目会重叠，不能相加，也不是承诺可节省的时间。编译器可能内联函数，因此没有把未单独显示的怪物基础属性路径解释为零开销。

## 两个独立候选

**怪物基础属性缓存**：按单位保存由固定怪物身份、难度和迷宫层数计算出的基础属性、等级和经验值，并检查游戏数据版本。缓存命中仍恢复基础等级与经验值，保持构造状态重置、等级操作后的原行为。buff 应用、到期、移除以及当前 HP/MP 不进入缓存。

**buff 类型索引**：用内部枚举表示属性计算所查询的 40 种 buff，一次重算建立直接索引及有序合计，神龛增益在普通 buff 后追加。等级、闪避和抗性仍逐项计算，保留浮点运算顺序。未参与属性公式的其他类型仍保存在单位的 buff 列表中。索引不跨重算复用。

怪物缓存初筛的三组计时有波动，其中魔像洞穴的中位数出现退步，所以没有据此决定保留。正式矩阵同时比较原版、仅怪物缓存、仅 buff 索引、两项合并，分别保存各版本源码和 WASM。

## 验证

- 怪物缓存、合并版本分别通过 3,482 个属性场景的 native/WASM 冻结 JS 对照。
- 合并版本通过 56 项完整战斗/轨迹/内存回归，加 6 项专精护符对照，包括 24 小时地下城、72 小时普通地图。
- Rust 单元测试 14 项通过。新增用例覆盖构造阶段重置、数据版本切换、临时 buff 到期、当前 HP 保留、JS 整数属性键排序、神龛追加顺序及非结合浮点加法。
- 格式检查和 workspace/all-targets Clippy（warnings 视为错误）通过。

## 正式矩阵方法

使用此前重建的 11 个三人队伍配置，每个模拟 24 小时、种子 7。每个版本、每个配置预热一次，正式测四次；四个版本轮换顺序，使各版本在四个位置各运行一次。中位数使用排序后中间两个数的平均值。

计时包含 WASM 模拟、结果序列化和 JSON 解析，不含初始化、哈希和 Playwright 回传。结果检查涵盖完整结果哈希、随机调用次数、事件总数和各事件类型计数，并比较此前 JS 的结果哈希及随机调用次数。只忽略日志中的现实时间戳。

这是固定重建输入的新对照，不是原始历史的随机战斗回放。原始数据、各版本产物、CPU profile、逐轮计时与本机脚本均在忽略目录 `.bench/rust-attributes-stage2/`，不提交、不上传。

## 合并版本的后续采样

正式计时结束后，对合并版本用同样方法独立采样；这些带 profiler 的运行不计入上表。

| 函数 | 巫师之塔 T4 | 地狱深渊 T3 | 魔像洞穴 T3 |
| --- | ---: | ---: | ---: |
| 属性重算（含子调用） | 17.3% | 17.6% | 17.8% |
| 消耗品触发流程（含子调用） | 19.5% | 21.9% | 22.0% |
| 消耗品触发流程（自身） | 4.9% | 6.9% | 5.2% |
| should_trigger（含子调用） | 5.4% | 5.3% | 5.8% |

全局 JSON 键查询自身仍约占 7.3%～10.4%，内存分配和释放也是主要开销之一。触发流程的包含子调用时间含消耗品执行、后续属性更新等，不能解读为约 22% 的纯条件判断成本，也不能与属性重算占比相加。
