# 三人星球与五人地牢的 Rust 内核优化实测

2026-11-23，在本机 Edge 的 WASM Worker 中，四项合用让两张三人星球的 24 小时模拟耗时下降 30.85% 和 10.96%，两张五人地牢下降 34.02% 和 23.46%。每张图的六轮正式计时里，组合版六轮均快于同期基线。

## 实现与测试口径

- 攻击统计为攻击者、目标和技能名称分配整数编号，用有序映射累计每种伤害或未命中次数。读取逐事件快照、分块结果和最终结果时，恢复原有 JSON 键、顺序和数值。
- 每次模拟独立缓存初始怪物模板，按怪物、难度和迷宫层数区分。每次刷怪都复制出独立单位，按原顺序重置、抽取冷却随机数并分配身份。
- 事件堆按单位的存储槽维护待执行普攻和施法的数量。入堆、弹出、按条件取消和清空都会同步更新计数。原有堆结构和同刻事件的处理顺序继续生效。
- 地牢日志在受击时记录实际 HP、伤害、来源等快照，最多保留最近 200 条，团灭时统一导出相同的 JSON。击杀、团灭次数和详细战报均参与结果核对。

基线是 `codex/rust-wasm-migration` 提交 `9f97f7e` 加上本地已核实的棋子晋升修正。隔离重建的基线 WASM 与修改前产物 SHA-256 相同。四个单项版本分别只包含各自的改动，另行构建四项组合。

测试环境为 Core i9-13900HX、Edge 157.0.4341.60。每个版本使用独立的常驻 Worker，所有模拟串行运行。同一地图统一使用种子 7，模拟 24 小时，关闭 HP/MP 时序，保留攻击统计和完整团灭日志。海洋星球和两个地牢来自仓库的公开合成队伍。熊熊星球来自本机已有的三人历史重建输入。

每图每版先预热两次，再正式计时六次。每一轮都轮换版本的执行次序，每版在六个位置各出现一次。共 48 次预热和 144 次正式计时。计时包括输入字符串传入 WASM、战斗、结果序列化和 JS 解析。模块初始化、游戏定义加载、输入准备、结果哈希和跨 Worker 传输在计时范围之外。降幅用各版中位数除以基线中位数计算。每图使用一个种子，不能外推到所有队伍、地图或设备。

## 一致性与内存

对每个测量版本，327 组序列化输出与基线逐字节相同。涵盖 1,192 个遭遇的 12,989 帧、19 个完整模拟、6 个连续模拟轨迹和重复读取分块结果。每次正式计时也核对完整返回字符串的 SHA-256，覆盖事件计数、RNG 次数、完整战报及输出顺序。

另开全新实例核对长场景。种子 7 的单人螃蟹 72 小时，基线与组合的 WASM 线性内存分别为 17.125 和 17.0625 MiB。种子 1 的五人海盗湾 24 小时导出 18,293,392 字节，分别为 193.375 和 193.8125 MiB。种子 42 的秘法要塞 6 小时也通过完整输出哈希核对。

四项优化合入本地内核后，通过了 22 个 Rust 单元测试、格式检查和 Clippy。仓库既有的遭遇逐事件对照、专精经验分配、连续模拟三组回归全部通过。

正式计时使用隔离构建的组合版。合入后重新构建的 WASM 与计时版的可执行代码段逐字节相同（748,676 字节），仅数据段有差异。另用最终 Rust 原生版和 WASM 版各重跑四张图，两者的完整模拟结果均与基线逐字节相同。[最终构建与逐图结果 SHA-256](benchmarks/rust-planet-dungeon-20261123/final-check.json)
