# Rust 统计操作类型化实验

日期：2026-10-05。基线为 `codex/rust-wasm-migration` 的 `3fc6fd4`，已包含结果计数的借用查询优化。

## 实现与边界

原调用链先用 `json!` 创建操作数组，`SimResult::apply` 再读取字符串标签、单位编号和数值。现在以内部 `ResultOp` 枚举传递攻击、死亡、消耗、生命/法力恢复、生命消耗、缺蓝、经验和遭遇完成操作：

- 字符串标签借用原值，不为中间操作复制字符串或分配 JSON 数组。
- 直接传递已有 `UnitId`，使用带身份检查的句柄访问单位，省去从 JSON 序号重新查表。
- `apply` 仍在原位置立即更新统计，事件顺序、浮点运算和结果 JSON 格式保持一致。
- 独立遭遇测试或逐事件轨迹模式仍在同一位置构造原来的操作数组。字段顺序、单位序号、`miss` 和伤害数值保持原样。
- 非有限数值在原来读取金额的位置仍被拒绝；仅生成轨迹时仍按 JSON 规则记为 null。缺失源单位仍跳过统计。

另测了对 `emit` 强制内联的版本，希望按调用点已知的枚举变体消除分发分支。它比普通类型化版的 WASM 大 4,976 字节，但同轮总体收益较低，最终不保留该内联标记。

## 正确性验证

- 普通类型化版通过 20 项 Rust 单元测试、格式检查和 workspace/all-targets Clippy（warnings 视为错误）。
- 新增用例覆盖单位槽位回收复用后仍输出单调序号、全部操作的轨迹格式、负零及非有限值。
- native/WASM 两端通过 1,191 个冻结 JS 场景、12,953 帧逐事件对照，包含 840 个触发器场景。
- 56 项完整模拟/轨迹/内存回归及 6 项专精护符对照通过，包括 24 小时地下城、72 小时普通地图和分块执行。
- 最终恢复普通类型化实现，并核对源码及重新构建的 WASM 与已验证的冻结候选一致。

## 两轮计时

使用此前重建的 11 个三人队伍配置，每次模拟 24 小时、种子 7，在 Edge 154.0.4258.37 的实际 WASM Worker 串行运行。计时包含模拟、结果序列化与 JSON 解析，不含引擎初始化、结果哈希及 Playwright 回传。

第一轮比较基线与普通类型化版。连续稳定预热至少 30 秒，本次 16 次；每配置、每版本再预热一次，正式计时四次，交替先后顺序。矩阵共 110 次，取四次中位数，合计 **21.380 → 20.992 秒，减少 1.8%**。9 个配置更快，地狱深渊 T3 慢约 5.0%，巫师之塔 T3 慢约 0.2%，因此继续测试内联候选。

第二轮同时比较三个冻结版本，稳定预热 18 次；每配置、每版本预热一次，正式计时三次，轮换顺序，使各版本在每个位置各运行一次。矩阵共 132 次（33 次预热、99 次计时），各配置取三次中位数。

两轮及稳定预热的完整结果哈希、随机调用次数、事件总数和各类型事件数全部一致，并与此前 JS 的结果哈希、随机调用次数比较；只排除日志中的现实时间戳。

最终保留普通类型化版：两轮总体减少约 **1.8%～3.1%**，第二轮强制内联仅减少约 1.9%，不值得额外增大产物。普通类型化版第二轮有 8 个配置更快，3 个更慢；它也不是每张地图都优于内联版。

单图波动明显，例如地狱深渊两轮一慢一快，巫师之塔 T3 第二轮退步约 7.1%。这些结果支持总体小幅收益，不能声称所有地图都提速，也不能据此确定单图稳定回退幅度。三次/四次中位数不是统计置信区间；不同轮的绝对秒数不可直接相减。

这是固定重建输入的新对照，不是原始历史的随机回放，也不是线上多 Worker 批量模拟的总耗时。原始输入、源码快照、产物、profile 和逐轮记录保存在忽略目录 `.bench/rust-typed-results-stage6/`，不提交、不上传。
