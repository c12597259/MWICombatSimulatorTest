# Rust 结果统计的查询与分配优化

日期：2026-10-05。基线为 `codex/rust-wasm-migration` 的 `e0b9c41`，包含此前的消耗品分类优化。本轮仅修改 Rust 的结果累计实现，保持实时 JSON 结果和现有统计规则。

## 实现

当前依赖的 serde_json 1.0.151 在执行 `Value` 的可写字符串索引时，会调用 `map.entry(key.to_owned())`，即使命中已有字段也会创建键字符串。原计数函数还会先读取同一字段，再执行可写索引。

本轮改动：

- 计数路径命中时使用 `get_mut` 借用已有值，仅首次出现的键走插入路径，保留初始值转换、字段插入顺序及逐次浮点加法。
- 顶层统计字段也进入同一借用路径，避免每次先通过可写索引取得统计对象。
- 攻击结果已是字符串时直接借用；数值结果仍按原规则转换成字符串键。
- 经验与缺蓝统计复用已取得的玩家条目。经验加成直接读取七个数值字段，去掉每次拼接 `skillExperience` 的临时字符串；专精分配、技能顺序和乘法括号不变。

结果仍随每条操作立即更新，轨迹、进度和最终导出继续读取同一个 JSON 对象。

## 验证

- 19 项 Rust 单元测试、格式化及 workspace/all-targets Clippy（warnings 视为错误）通过。
- 新增计数函数与旧实现的逐步序列化对照，覆盖嵌套字段、覆盖非对象值、数值键插入顺序、负零、非有限值和非结合浮点累加，共检查 544 个中间状态。
- native/WASM 的 56 项完整模拟/轨迹/内存回归及 6 项专精护符对照通过，包含 24 小时地下城日志、72 小时普通地图回收和分块执行。
- 最终源码与冻结候选逐字节一致，WASM 哈希与正式矩阵产物一致。

## 计时方法

继续使用本机重建的 11 个三人队伍配置，每次模拟 24 小时、种子 7，Edge 154.0.4258.37 的实际 WASM Worker 串行执行。开始时连续交替运行至少 30 秒，本次稳定预热 18 次；之后每版本、每配置预热一次，再正式计时四次，并交替先后顺序。

正式矩阵共 110 次运行（22 次预热、88 次计时）。每配置取四次的中位数，偶数中位数取中间两个值的平均。计时包含模拟、结果序列化和 JSON 解析，不含初始化、哈希计算及 Playwright 回传。

18 次稳定预热、110 次矩阵运行均通过完整结果哈希、随机数调用次数和事件计数检查，并与此前 JS 的结果哈希和随机调用次数比较；只排除日志中的现实时间戳。原始输入、逐轮记录、脚本及版本产物保留在忽略目录 `.bench/rust-results-stage5/`，不提交、不上传。

## 后续采样

对巫师之塔 T4、地狱深渊 T3、魔像洞穴 T3 分别预热一次、采样两次，CDP 间隔 1 ms，排除 idle。九次结果检查通过，采样计时不计入正式结果。

`SimResult::apply` 含子调用占比分别为 13.2%、12.8%、11.5%，上一轮约为 18.2%、17.2%、16.3%。`increment` 含子调用仍约占 7.1%～8.0%，且与新的 `increment_entry` 重叠，不能相加。不同运行状态、内联和采样误差都会影响这些比例，不能直接视为节省的总时间。

下一步值得单独测试高频攻击、恢复等统计的直接调用：目前 `emit` 先创建临时 JSON 操作，`apply` 随后又解析字段。可尝试在常规模拟中直接传递类型明确的参数，仅在需要逐事件轨迹时构造原格式 JSON；继续保留更新顺序和轨迹输出，再用同样输入验证收益。
