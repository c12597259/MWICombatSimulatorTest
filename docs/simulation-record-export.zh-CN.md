# 临时模拟记录导出

“模拟历史”旁的 **导出全部地图记录（临时）** 按钮会下载一个 JSON 文件。

- `records`：此浏览器、此站点下所有已保存历史，包含所有地图、所有队伍及重复模拟，不受历史面板当前地图筛选影响。配装快照已经解压，可直接读取。
- `latestRun`：本页最近一次完成的模拟的完整输入、结果与耗时。使用“模拟全部地图”时，这里包含整批地图、难度和对应的全部结果。**批量结果请在开始下一次模拟或刷新页面前导出**，现有历史功能不保存批量模拟。
- 新完成的单图历史在 `teamSnapshot.simulationRecord` 中额外保存实际 Worker 请求、耗时、构建标识和浏览器环境；刷新后仍可导出。历史只保存结果摘要，不持久化完整战斗日志。
- 旧历史只有原先保存的队伍快照和结果摘要，缺失的请求、额外增益或耗时不会用当前界面值补齐。`replayAvailability` 标记为 `team-snapshot-only`。无法解压的快照单独标记错误，不影响其他记录导出。

## 收集三人普通地图样本

1. 导入队伍，在模拟设置中选择三人和模拟时长。
2. 勾选“模拟全部地图”，选择要跑的普通地图，开始模拟（沿用现有功能，会遍历地图支持的难度）。
3. 等到整批完成，点击“导出全部地图记录（临时）”，保留下载的 JSON。

所有数据由浏览器本地下载，不自动上传。导出包含角色名称、配装和触发器等队伍信息。

## 性能比较时的口径

`simulationTimeLimit` 是模拟世界时长（纳秒），`timing.elapsedMs` 是实际等待时间（毫秒），包含 Worker 通信，不包含结果展示和导出文件的时间。批量记录的耗时是**整批并行运行总耗时**，不是每张地图耗时；逐图比较需要按导出的请求重新测量。

批量 `request.zones` / `request.labyrinths` 与 `result` 按索引一一对应，队伍顺序及槽位标识原样保留。`recordCount` / `mapCount` 只统计持久化历史，当前批量目标数读取 `latestRun.request.zones.length`。

当前 JavaScript Worker 使用未设种子的 `Math.random`，所以这些输入可用于反复测量性能和统计误差，不能保证复现同一条随机战斗轨迹。
