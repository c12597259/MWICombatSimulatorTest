# JS 属性重算优化

日期：2026-10-04。基于 `codex/rust-wasm-migration` 的本地 JS 引擎。

## 改动

- 每次属性重算只建立一次 buff 索引，同时保存有序明细和按原顺序累加的合计。
- 玩家神龛等级规范化一次，神龛增益按原有顺序追加到普通 buff 后；各属性读取直接复用索引，避免重复拼接数组和累加。
- 对没有对应 buff 的读取使用共享空值，减少临时数组与对象。
- 预先保存等级和近战属性的字段名，避免每次重算拼接字符串；闪避明细只读取一次；攻击速度求和移除中间数组。
- 等级、闪避和抗性仍逐项应用增益，保留浮点计算顺序。索引只在一次同步重算中有效，并用 `finally` 清理。

没有减少模拟时长、采用近似公式、跳过事件或取消增益变化后的属性更新。本轮未改动 Rust 属性计算。

## 验证方式

- `npm run test:combat`：14 项通过，新增共享 buff 修改、神龛变化、到期/重置、非结合浮点加法与异常后读取回归。
- `npm test`：102 项通过。神龛测试原先用 data URL 直接加载无依赖的 `CombatUnit` 源码；拆出辅助模块后，测试加载器也同步解析该模块。
- `node bench/parity.cjs --reference js-reference-2783b09-p0`：9 个公开场景完整结果、随机数调用次数及事件计数全部一致，包含地下城、团灭、迷宫、神龛与额外增益、HP/MP 时序。
- 实际队伍对照使用此前重建的 10 张普通地图、11 个三人队伍配置，每个模拟 24 小时，固定种子 7。历史导出缺少当时种子与额外增益，本轮沿用前轮重建输入，不能视为原历史战斗回放。
- 修改前后的 production bundle 分别载入独立 Edge Worker，串行交替运行；每个配置、版本预热一次，再测三次并取中位数。计时包含请求解析、模拟、结果序列化及 JSON 解析，不含模块初始化和结果哈希。
- 对照完整结果规范化哈希与随机数调用次数，只忽略团灭日志中的现实时间戳。数据、请求、旧版与候选 bundle 以及逐轮报告均保存在本机忽略目录 `.bench/attribute-recalculation/`，未包含到提交或站点。

## 复跑

本机专用脚本 `.bench/attribute-recalculation/run.cjs` 读取 `.bench/history-benchmark/prepared-private.json`，保留 `baseline-browser.js`，重新构建 `candidate-browser.js` 后进行对照。需要可加载 Playwright 的 Node 运行时和 Edge。原始队伍资料不加入仓库。

不要用重新构建的当前版本替换 `baseline-browser.js`，否则会变成同一个实现自比。也不要将本轮计时和前轮不同时间段的绝对耗时直接相减；本报告使用同一轮交替测量的两个版本。
